1. /opt/offsite-backup/rclone.conf 원문 (nobody 권한으로 읽음)
   [offsite]
   type = sftp
   host = backup.hartley-group.internal
   user = svc-backup
   pass = HZKAxfnMj-nLm59X9gpcC2ohjQL-WqVT6yRsNw   (rclone 자체 난독화, 암호화 아님)
   shell_type = unix

2. rclone reveal 결과 (대상의 /usr/bin/rclone 사용)
   명령: rclone reveal HZKAxfnMj-nLm59X9gpcC2ohjQL-WqVT6yRsNw
   결과(평문): iXzvcib3SrpZ

3. 재사용 확인
   위 평문 비밀번호가 svc-backup이 아니라 로컬 시스템 계정 scott(uid 1000)의 SSH 로그인 비밀번호로 그대로 재사용됨을 SSH 로그인 성공으로 직접 확인 (loot/E14 참고).

4. marcus 계정 접근
   비밀번호가 아니라, wide-links 취약점으로 공격자가 생성한 SSH 키페어(ed25519, 코멘트 htb-abducted)를
   /home/marcus/.ssh/authorized_keys에 심어 키 기반 인증으로 접근. marcus의 실제 로그인 비밀번호는 확보/추정하지 않았음.
   심은 키는 작업 종료 시 삭제 완료 (marcus ssh로 rm 실행, 이후 해당 키로의 재접속 시도가 인증 실패하는 것으로 삭제 확인).
